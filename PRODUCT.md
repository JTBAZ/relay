# Relay product context

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Artists managing artwork across connected publishing platforms. This design work concerns the Posting Recipes prototype; other Relay surfaces retain their own contracts.

## Product Purpose

Arrange repeatable routes from a new source publication to destination accounts, with filtering, image treatment, description handling, timing and explicit publication authority. Success is a saved recipe whose future behavior the creator can predict before enabling it.

## Operating Context

The user confirmed on 2026-10-18 that reusable recipes for future posts should receive the clearest, fastest path. A selected uploaded artwork is a secondary context. The current artifact is a standalone interactive HTML file with fictional accounts, local browser storage and an execution simulator. It makes no live API calls, posts or emails.

## Capabilities and Constraints

The proposed R1 contract is docs/studio/posting-recipe-build-plans/PRODUCT-CONTRACT.md. Connected Patreon intake, AND filters, 1–16 routes, bound X/DeviantArt destinations, one image, original/Previewizer treatment, source/edit/saved descriptions and reviewed Coach treatment. Timing includes elapsed days, an explicit local clock, and first/last current/following reference month. Actual per-destination publication receipts unlock dependent routes. Default preselects; Always on enrolls; neither grants automatic posting. R1 publishing is creator-finished guided handoff. Remote approval and automatic API delivery remain gated follow-ups.

## Brand Commitments

Relay. Conversational concise language: When I post to…, Also send it to…, And then…. User requested modern minimalist GitHub-informed product UI, rounded geometry, contextual controls, smooth fades and no popup wizard. Preserve the creator's control and exact account/media/copy context.

## Evidence on Hand

Current code and product/build contract under docs/studio/posting-recipe-build-plans/. Prototype demo/recipe-editor.html and editor-preview.jpg show the incumbent. Fictional account names and descriptions are demonstration data, not a deployment or connector claim.

## Product Principles

- Make reusable behavior predictable before saving.
- Keep routing, scheduling and transformations distinct but visibly connected.
- Reveal detail when it becomes relevant; retain values when hidden.
- Preserve explicit authority and actual publication evidence.
- Scope prototype changes separately from production implementation.
