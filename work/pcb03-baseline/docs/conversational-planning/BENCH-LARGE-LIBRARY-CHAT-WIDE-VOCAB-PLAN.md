## Change and boundary

Remove only the arbitrary `MAX_VOCAB_ENTRIES = 64` refusal in `src/editor-bench/large-library-chat.ts` and its now-unused counter. Keep the **entire deduplicated vocabulary** from every post, in stable order, with the existing **8 KiB UTF-8 vocabulary** and **16 KiB serialized `{input,tools,responseSchema}`** limits, request length/date candidate bounds, one `gpt-5.6-luna`/none provider call, request-local date schema, and exact grounding plus shared exhaustive matcher/refinement. Refuse the whole turn before the provider when either byte bound is exceeded; never truncate, rank, page, sample, or silently omit entries. Remove the `vocabularyEntries` property from `LARGE_LIBRARY_CHAT_LIMITS` or make it explicitly byte-bounded; do not replace 64 with another unexplained numeric entry ceiling. No lexical retrieval, embedding/index stage, tool loop, second model call, full post-row prompt, ID enumeration, synonym parser, or schema/guard weakening.

The byte limits are finite: this permits compact vocabularies above 64 entries, not arbitrary cardinality or arbitrary distinct names. Quality at larger or semantically dense vocabularies remains unmeasured until a specific gate passes. The old <=40 interpreter, public grounded route and schema, real Library, and existing compact mock default must retain their behavior.
