## Contract

Add `runMockLargeLibraryChat({latestRequest,state,snapshot,provider,now,signal})` in `src/editor-bench/large-library-chat.ts`. `snapshot` is constructed by a local synthetic fixture/proof harness and is never a browser-supplied catalog. The handler accepts only selection/refinement requests; an edit, posting, scheduling, or mixed request is clarified as a whole. It validates `state` against the snapshot revision before provider dispatch. Existing `RetrievalRefinementState` v2 carries selected/excluded IDs, but the model receives only `statePresent`, `selectedCount`, and `excludedCount`—never those ID lists, post rows, descriptions, or media.

Build one **complete deduplicated vocabulary from the entire snapshot**, independent of page order or match positions:

```ts
type MockVocabulary = {
  tags: string[];
  works: Array<{id:string,title:string}>;
  series: Array<{id:string,title:string}>;
  collections: Array<{id:string,title:string}>;
  publishStates: string[];
  mediaTypes: string[]; mediaRoles: string[]; processingStatuses: string[];
  mentionedPosts: Array<{id:string,title:string}>;
};
```

`mentionedPosts` contains **every** owned post whose full effective visible title occurs literally, case-insensitively, in the latest request; it is empty otherwise. This is a name lookup, not a first-page/top-K candidate list. Include all duplicate names so a post-ID selector can be refused as ambiguous. Do not send arbitrary post titles, effective descriptions, dates, or media IDs. A description/title predicate uses a phrase copied from the request and is evaluated later against the complete snapshot. The vocabulary includes every distinct tag/family/facet value across all 1,001 posts. If it exceeds **64 entries in total or 8 KiB UTF-8 serialized**, or the complete serialized model request **`{input,tools,responseSchema}`** exceeds **16 KiB UTF-8**, clarify **before** calling the provider; do not truncate/rank/sample. Keep latest request <=4,000 characters and existing date grammar. This is a bounded-vocabulary capability: a larger Library with many distinct values may honestly refuse, even when its post count is within BLR-01 limits.

Use the existing `createEditorBenchRuntime` provider (`gpt-5.6-luna`, reasoning none in the current dev config) and **unchanged** `REAL_LIBRARY_MODEL_RESPONSE_SCHEMA`, whose strict root object is `{result:anyOf(selection,clarification)}` with `MetadataSelection` and `intent:null`. The one prompt explains `all`/`any`/`none`, real-only add with catalog base, stateful narrow, removal exceptions, sticky exclusions, literal description/date quotes, and untrusted vocabulary strings. It must preserve every explicit criterion or clarify, not silently reduce a compound request. It may map a quoted request word such as “coast” to offered canonical tag `coastal`, or a named series to an offered ID; it may not invent values or IDs. No retry, tool call, per-page model call, or prompt expansion by post count.

After model output, apply a **vocabulary-grounding guard** before the existing full-snapshot matcher. Each metadata predicate quote must be an exact substring of the latest request; description/title values must occur literally in their quote; tag/status/media canonical values must be in the complete offered vocabulary; work/series/collection IDs must be offered and grounded by their unique visible name in the quote or literal ID; post IDs must be among `mentionedPosts` with unique visible title. Date values use the existing `resolveDatePredicate` and trusted London clock. Unsupported fields, ambiguous duplicate names, malformed shape, and unknown offered values clarify without changing state. Generic runtime detection of a model-omitted criterion is **not** claimed; the focused oracle proof must catch that quality failure. This guard is **separate from** the existing public BLR `resolve-grounded` strict-literal ingress, which stays unchanged. Then call the shared real selector and `selection-core.ts` refinement on **every post** in the snapshot (with canonical vocabulary membership authority), preserving all/any/none, empty matches, global exclusions, add union, narrow, and remove exceptions. Avoid a second parser, duplicate reducer, or a model-generated ID enumeration.

The handler returns the existing BLR selection/state/result shape plus `{usage}` and a provenance of `model_interpretation` or `none`; malformed/provider/overflow/stale errors leave state unchanged. One small `scripts/editor-bench-large-library-chat-demo.mjs` can invoke a reusable pure synthetic fixture module. Its default zero-cost stub runs **only a declared canned request/output example** and never claims to interpret arbitrary user text. Explicit `--live` accepts user requests and keeps state in memory across turns; explicit `--live-proof` prepares the fixed requests, expected oracle arrays and conservative ledger preflight for root to inspect **before** any paid call. The demo remains mock-only and shows expected versus actual selected/excluded ID arrays. No new authenticated real-DB vocabulary API, two-read handshake, Next bridge, webpage, gallery write, posting path, schema change, or production enablement.
