## Root decisions already recorded for this draft

1. **Existing-post reuse requires explicit intent:** `prepare_post_draft.target_post_id === snapshot.source.post_id`, with an existing-post source and fresh ownership/relationship validation. A null target does not authorize reusing the source as the requested finished post or creating a new draft. Current repository source-post pointer acceptance is broader; its narrow guard change needs a dispatched resolver slice below.
2. **Preparation must not stale its own source:** the CP-08 production fingerprint excludes `autopostDraftId`, reservations, authority statuses and generic `updatedAt` values changed solely by those writes. It retains actual source/content versions and relationships. Do not silently refresh an approved fingerprint when publishing creates a new post relationship; that later transition requires a separately reviewed source/authority handoff. CP-09 rechecks genuine drift before new writes.
3. **Preview provenance stays a gap:** creator-owned ready media alone cannot qualify as the preview exported for a particular plan/source/template. CP-09 keeps `preview_media` fail-closed. The separately gated CP-11 design below does not authorize schema work now.
4. **CP-09 source/output and attention mapping are ratified:** explicit existing-post reuse produces a checked post pointer; eligible staging produces a correlated draft. A timed source preparation may create `make_post` / Patreon attention, with the fixed exact label **`Review Patreon post`**, exact approved note, `remindMe:true`, and strict checked-post/null-with-correlated-draft binding. Preview and engagement remain blocked.
5. **Cap serialization is bounded to CP-09 callers:** lock the provisioned creator Tenant for each CP-09 output transaction and recheck the existing **20 active draft soft cap** for a new draft. Legacy draft writers do not take that lock. Concurrent legacy creation can overshoot 20; this is an accepted limitation, not a new globally enforced hard cap or permission to retrofit all legacy writers with Tenant requirements.
6. **Owning reservation core must protect media:** factor READY/origin/unattached/creator predicates and exact update-count assertion into the draft service's reservation core, used by CP-09 and its existing save/patch callers. No weaker CP-only precheck or copied reservation implementation. Preserve approved title/note text exactly or return the finite normalization gap; never silently trim/change it.
7. **Source diagnostic correction has a bounded meaning:** the current compiler puts the existing-post `draft_only` clarification before its unconditional empty-source-media check, unifying attached-media/post-only guidance. The old unconditional check already blocked post-only requests; this is **diagnostic consistency, not a previously executable empty-helper bypass being fixed**. Explicit existing-post handoff still requires nonempty selected attached media. A primary `delivery_intent:"none"` does not establish an accepted creation purpose (the new-plan compiler rejects it); an independently saved/null-target empty helper remains blocked by the materializer source map. Do not claim the interpreter shape alone proves that purpose. Teaser-only remains `contract_gap`. No source/discriminator/media-copy expansion is inferred.
8. **CP-11 assurance boundary is accepted:** browser-render association is creator-asserted, with server-validated plan/source/template/upload identity. It is not server rendering or pixel proof. Exact provenance schema and deliberate re-export policy remain separately gated CP-11 reviews.

Other proposals in this document remain subject to root review; this is not a frozen CP-09 dispatch contract.

## Narrow transaction and correlation seams

Support short shared transactions for each eligible authority plus its pointer, with recovery by the existing unique key. No authority create is safe merely because the caller checks for a key before calling an unmodified service. The current service accepts no key, so it could commit an uncorrelated row and crash before anyone can repair its pointer. Do not ship that sequence as an idempotent adapter.

Proposed owning-service seams, names provisional until root accepts signatures:

- In `autopost-draft-service.ts`, add a server-only `saveConversationalDraftInTransaction(tx, input)` taking a finite creator/step-key/media/title payload and forcing `generate:false`. Factor/reuse the existing draft normalization/create/reserve core; do not duplicate an unreviewed draft writer in `materializer.ts` or change legacy defaults. All uniqueness checks and key insertion happen in the transaction. Preserve the public `saveAutopostDraft` behavior for ordinary callers.
- The draft seam locks eligible media rows in stable ID order, rechecks creator/origin/READY/unattached/unreserved state in the transaction, inserts the correlated draft, reserves every requested row using those same predicates, and asserts the reservation update count equals the exact requested count. A failure rolls back both draft and reservations. Re-query the key **before** media/cap checks so a replay of the same correlated draft does not fail merely because that draft now owns the media. A different step cannot steal it.
- Factor one internal `reserveMediaForDraft(tx, draftId, creatorId, mediaIds)` core rather than duplicating it for CP-09. The claim predicate is exact unique IDs + creator + `ingestOrigin in [DISCORD, RELAY_UPLOAD]` + `processingStatus:READY` + `primaryPostId:null` + unreserved-or-this-draft. Assert `updateMany.count === mediaIds.length`; CP-09 rejects duplicate/noncanonical IDs before this call. Existing release of only this draft's previous reservations remains inside the same transaction; a failed claim must roll it back too. Empty legacy nudged drafts still release/return without a media claim. Existing save and media-changing patch paths reuse this strengthened core, protecting their prior-read race as well. This intentionally tightens unsafe reservation success, not ordinary legacy normalization/default behavior. Minimum legacy regression scope is existing `tests/autopost-draft-service.test.ts` plus focused save **and** patch races where media is claimed, becomes not READY, changes origin or attaches after precheck; assert rollback/no unowned media and unchanged ordinary generate/nudged/media-replacement semantics. Mock rollback assertions alone are insufficient; reviewed disposable proof must exercise the actual owning methods/core.
- Recheck the 20-active-draft soft cap within CP-09's serialized per-creator preparation transaction, before inserting a new correlated draft. Reusing its key consumes no new slot. Root selected serialization among CP-09 callers only: concurrent legacy writers can overshoot this soft cap. Do not claim a new global invariant or add Tenant locking requirements to legacy/headless draft callers.
- In `creator-schedule-event-service.ts`, add a narrow `createConversationalAttentionEventInTransaction(tx, input)` for the reviewed `make_post/patreon` payload and step key. It does not accept arbitrary event JSON, create a Relay post, look up/confirm platform URLs, or emit a legacy playbook run. Shared type/date/post validation may be factored; ordinary Studio Core endpoints remain unchanged. Engagement insertion is not implemented until CP-13.
- In `persistence.ts`, expose the closed **server-only** `prepareOutput` operation below. The repository derives authority payloads from its locked validated snapshot and passes its transaction to the owning helpers; the materializer is an orchestrator, not another authority writer. It accepts no client ownership callback, unchecked authority row, arbitrary Prisma query or generic transaction callback. Do not call public `putCheckedPointer` from inside that transaction: it opens its own transaction and would not share the lock/commit boundary. Root must approve these exact typed seams before a builder touches this accepted repository.

For each eligible output, in dependency order:

1. Enter the short creator/approved-plan transaction; re-read the current source node and exact key. Revalidate fresh live links needed for that output.
2. Look up the authority by **both creator and exact correlation key**, and the pointer by `(planId,nodeId,slot)`. An authority owned by someone else or with the wrong purpose/parent is a scoped failure. An occupied pointer to a different row conflicts; no reassignment.
3. If an authority exists, verify it and reuse it without reapplying initial content/time/status. If absent, create it with the key through its owning transaction helper. Unique races roll back and enter a bounded winner re-read; no new key or second create on conflict.
