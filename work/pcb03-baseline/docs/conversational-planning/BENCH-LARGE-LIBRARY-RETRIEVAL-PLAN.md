# Large Library retrieval seam: model-free, exhaustive selection

Status: **BLR-01 implemented by Luna High and accepted by root as a grounded backend connector, 2026-10-18; planned by Sol High.** Add a read-only, model-free resolver for an **already-grounded** real-Library selector. Keep the accepted <=40-post BLS interpreter, prompt, UI, and mock default unchanged. This advances the retrieval connection for later assembly without promising that natural-language selection of a larger Library works today.

## Decision boundary

Sending every Library title, tag, work, series, collection, and description to the cheap model scales prompt cost with Library size. Sending only a bounded top-K/page loses results. A query-only parser without the catalog loses vocabulary grounding: “coast” may mean an unseen `coastal` tag or a named series may map to an opaque ID the model never saw. Neither is a no-quality-loss replacement for the current bounded path. Therefore this ticket does **not** activate a new large-Library chat path, add a weaker parser, raise the existing 40/80/48 KiB limit, or claim semantic parity for unseen catalog vocabulary. If the user's condition means full existing natural-language coverage on arbitrary large Libraries now, defer that product capability. The proposed resolver has **zero** model calls and prompt tokens; it accepts only a caller-supplied selection already grounded in the latest request and checks it with the existing strict rules.

## Snapshot and exact matching

Add `loadLargeRealLibrarySnapshot` beside `loadRealLibraryCatalog` in `src/editor-bench/library-selection-catalog.ts`, sharing existing effective-metadata normalization with separate large-snapshot bounds so the old 40-post path remains unchanged. Load all active posts for the authenticated creator in stable **`id asc` keyset pages of 100** inside one read-only Prisma `RepeatableRead` transaction with a **30-second timeout**. Bound the complete snapshot to **1,024 active posts, 4,096 distinct current active media IDs, and 16 MiB UTF-8 normalized selector metadata**; read a 1,025th post/4,097th media sentinel and refuse the whole request on overflow. Also refuse an individual value whose size would exceed the total bound. Never truncate a title, tag, relation name, or effective visible description, and never treat the first page as the complete Library. Missing current `PostVersion`, failed association read, or inconsistent owner relation refuses the snapshot. Include posts with zero media. These finite bounds are a connector limit, not an arbitrary-Library guarantee.

Reuse `resolveLibraryPosts` in batches of at most 100 for effective naming, current description (including a deliberately empty overlay), and tag add/remove deltas. Reuse `stripHtmlForSearch` for full literal visible-description matching. Read owned work/series/collection relationships, current active media facets, `Post.createdAt` and latest `PostVersion.publishedAt` exactly as BLS does; no inferred series, filename, upload/sync-as-publication date, image contents, or metadata write. Load and hash **all rows within the same transaction**, using account ID + creator ID + the entire canonical `id asc` normalized selector-relevant snapshot (including names, dates, media facets, empty description and tag deltas). Reload and recompute it for each turn; stale/foreign state returns 409 before matching. No HMAC or database state table is necessary because this is read-only selection, not write authority. DB latency and CPU grow with metadata size, bounded by these limits; only model cost stays zero.

Extract the pure real selector and refinement application currently embedded in `src/editor-bench/real-library-selection.ts` behind a small shared function. It accepts the normalized complete snapshot, latest request, trusted Europe/London clock, existing `MetadataSelection`, and state. It validates the existing field set, schema, exact latest-request quotes, literal description phrase, supported date grammar, unique visible-title grounding for `post_id`, owned IDs and known values. For this direct connector, text values must occur literally in their quote; an opaque work/series/collection ID must occur literally in the request **or** resolve from a unique exact visible owned name in the quote. Ambiguous names clarify, never pick a member. This stricter ingress prevents client-invented contextual IDs without changing the accepted BLS chat path. It then evaluates `all`/`any`/`none` against **every** post before applying the existing `selection-core.ts` reducer. `add` requires catalog base; stateful replace narrows current selection; remove resolves its whole expression with `none` as an exception, then stores removed IDs as sticky exclusions; positive `none` remains globally sticky across later additions. Empty valid matches commit empty state. Errors, ambiguity, cancellation, and overflow commit nothing. For selectors that pass this explicit grounding contract, effective matching is identical to the current real resolver on the same normalized data; only the accepted snapshot size changes.

Keep state separate from BLS: `{v:2,scope:'real_library_retrieval',catalogRevision,selectedPostIds,excludedPostIds}`. IDs must be canonical `id asc`, unique, owned, disjoint, and at most 1,024 total; each ID is at most 200 characters. The model sees none of these IDs in this ticket. Give this route a **dedicated 256 KiB JSON parser before the existing global 100 KiB parser**, leaving the existing BLS body limit untouched; cap latest request at 4,000 characters, aggregate selector quotes at 8 KiB, and reject any whole body exceeding 256 KiB without truncation. A stale revision or invalid state is rejected before evaluation. A selected/excluded state is a session preference only; all actual Library authority comes from the fresh authenticated snapshot. No current BLS state migration occurs.

## Narrow wire and ownership

Dev-only `POST /api/v1/editor-bench/library-selection/resolve-grounded` with `authenticateCreator(req,{readonlySession:true})`; no Studio Core publishing gate. Body:

```ts
{
  latestRequest: string;                  // <= 4,000 chars
  selection: MetadataSelection;          // existing strict selector schema
  state: RetrievalState | null;          // null only for initial selection
}
```

Response data: `{scope:'real_library_retrieval',catalogRevision,status:'selected'|'unchanged'|'clarification',selection:{postIds:string[],changed:boolean},refinementState:RetrievalState,result:{matchedPostIds:string[],selector:MetadataSelector|null},message:string}`. No media IDs, post metadata, catalog rows, model usage, signed posting token, or mutation. Reuse BLS error codes where applicable (`stale_library_selection`, `catalog_incomplete`, `catalog_too_large`). An invalid or unsupported grounded selector returns clarification with unchanged state; overflow and stale return whole-request errors. The endpoint is a **connector for later trusted interpretation**, not a new public client flow. A later result-page endpoint may use revision-bound cursors for display, but page boundaries must never define match scope. Do not add UI or Next model bridge in this ticket. The existing <=40 route and optional UI source remain unchanged.

**Single root-approved Luna High backend ticket:** own `src/editor-bench/library-selection-catalog.ts`, `src/editor-bench/real-library-selection.ts` (pure extraction with current behavior preserved), `src/editor-bench/real-library-selection-routes.ts`, and `src/server.ts`; a small focused test file only. Use `Set`/indexed membership where needed to avoid quadratic scans at 1,024 posts; do not change matcher language. No DB schema/migration, model parser, vector search, saved search, new framework, Next/client changes, or frontend ticket. Keep the mock demo default. No paid worker calls or further paid proof is authorized or needed for this model-free seam. Frontend tests, lint, typecheck, build, and browser QA remain deferred; run focused backend tests/build.

## Gate for claiming completeness and cost

Use one bounded synthetic **1,001-post** case and an authoritative full in-memory scan over its normalized rows. Include matching posts after page 40 and after page 1,000, a late-page series member and exclusion, tag override removal/addition, empty description override, a long description with a match near its end, zero-media post, null publication date, duplicate visible titles/named relations across distant pages, sticky removal with `none` exception followed by add, and stale owner/revision. Compare exact matched, selected and excluded ID arrays against the authoritative scan in the connector's `id asc` order; prove no top-K/first-page leakage and no partial success on a 1,025th post, 4,097th media, or byte overflow. Verify equal **match membership and refinement behavior** on the same <=40 metadata while leaving the old route's own display order untouched; the new route never constructs a provider or changes model input. These are focused backend cases plus existing backend regressions/build, not a new evaluation framework. This proof establishes exhaustive deterministic matching **within the connector's bounds** and zero additional model calls/tokens; it does not establish that a cheap model can interpret all large-Library natural-language requests without seeing vocabulary. That later activation needs its own bounded vocabulary/quality evidence and explicit architecture approval.
