# CP-09a2 — Owning draft preparation and reservation core

Root accepted as owning-service infrastructure, 2026-10-17. `saveConversationalDraftInTransaction` accepts a caller transaction and bounded server-derived correlation key/media/title, reuses the exact correlated authority before fresh content/cap/media checks, and otherwise prepares one manual drafting/draft-post row with null body/style/intent/performance goal and empty workspace. It preserves exact approved title/media order and locks a sorted copy of eligible media IDs with parameterized schema-qualified SQL. Caller-owned creator/plan locks and current approved-context checks are still required; no route calls this helper yet.

One normalized create core serves both the new helper and ordinary save. One shared reservation core serves conversational preparation and legacy save/media-changing patch. The claim requires the exact creator/requested IDs, READY staging origins, no canonical post and unreserved-or-this-draft state; count mismatch throws `ConversationalDraftReservationError`, inheriting the existing validation-error contract, through the outer transaction. It is not swallowed after draft creation or reservation release.

Root independently passed 23 focused tests (10 helper and 13 legacy) and the backend build; worker strict targeted TypeScript passed. Tests cover bounded exact payload/order/title/cap, occupied key/foreign owner, staging loss, unexpected reader failure, zero generation/style/mounted-context calls, and save/patch claim-failure propagation. These are mocked predicate/error-path tests: actual PostgreSQL rollback, races, per-creator cap serialization and correlated pointer recovery remain CP-09c2 gates. A concurrent legacy writer can still overshoot the existing soft cap; no new global hard cap is claimed.

Only the owning draft service and its two scoped test files changed in this slice. No schema, ordinary database, provider, ledger, server enablement or publication change occurred. CP-09a3 attention helper is dispatched separately; repository/materializer/integration remain incomplete.
