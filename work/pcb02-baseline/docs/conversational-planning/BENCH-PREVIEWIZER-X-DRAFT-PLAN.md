## Review and confirmation

Show **Review X draft** beside each selected post with a current completed Previewizer receipt. `POST /conversation/x-draft/review` accepts only `{sessionId,revision,postId}`. The server requires the authenticated creator, active X goal, selected fixture post, owned completed JPEG receipt, unchanged source/template binding and a recorded copy choice. It derives X `postText` from the post's **current effective title** for `existing_titles`, or from the already grounded literal common copy. It checks trimmed nonempty text and X's limit; it never generates or truncates copy. The response shows the exact outgoing text, source title, current export thumbnail/link, source-to-variant field diff, and a clear “Unscheduled mock draft; nothing posted” label. No record is created by Review. Only one pending review lives in the existing conversation; reviewing another item or starting a new turn invalidates the old one.

The review token binds creator, session, post, revision/generation, source version/fingerprint, selected original media ID, **confirmed preview media ID plus JPEG hash**, initial template ID/config hash, exact copy/variant hash, pending ID and expiry. `POST /conversation/x-draft/confirm` accepts only session ID and token. Under the existing session `confirming` guard, it rechecks all bindings and the active pending review before committing; stale/foreign/removed/replaced exports conflict without a write. The adapter's deterministic identity deduplicates the same approved facts. An exact successful token retry returns its immutable **creation receipt** plus the current conversation snapshot, even after later turns; a different stale token conflicts. Preserve the active goal, choices, selection and other items' previews after one confirmation.

Use `exactBenchVariant(source, 'x', copy)` and the existing `buildDistributionPlanCreateData` / `buildDistributionVariantCreateData` in an additive **draft-only** builder/commit method of `createBenchDistributionVariantAdapter`. It creates the same mock plan and `PostDistributionVariant` shape with `status:'draft'`, assistant off, `scheduledFor:null`, revision-0 approved copy and source/field-diff provenance. There is **no event row or invented due date**. Keep legacy V3's `{plan,variant,event}` builder, signed wire, edit lane and routes unchanged; an unscheduled draft need not enter the old event-linked edit API in this slice. Put the mock export ID in the plan's `preview_media_id` binding and `media_version:'preview'` in X variant platform fields, using the existing media-binding helpers. Verify that resolving variant media yields only that export ID. Original media IDs belong in immutable source provenance, never as a fallback attachment. The mock ID is not a real Library media ID and must never reach production package/publishing paths.

Confirmed drafts must not point at bytes later freed by selection or template changes. Pin the same confirmed JPEG Buffer in the **conversation session** under the draft's immutable export ID and receipt; share the Buffer for identical reviews, and count unique retained bytes under BPV-01's 4 MiB/session and 32 MiB/global caps. Cap draft receipts/versions at 32 per session and adapter draft-only rows at 1,024 per API instance; reject further creation honestly instead of evicting a confirmed draft. This bounds orphan rows after session expiry without a GC service. Later selection, template, source or copy changes invalidate an unconfirmed review and may clear the active preview receipt, but keep already confirmed draft rows, creation facts, revision-0 history and pinned export unchanged. Pins expire with the session and their bytes leave the existing memory count; after expiry the draft is an ephemeral historical row only, and scoped mock media reads must fail rather than fall back to the original image. Add an authenticated, same-origin read-only JPEG endpoint for an active receipt or pinned export, with creator/session ownership and private no-store response headers, so the review visibly displays the **actual exported bytes**. Do not expose Blob data or unrestricted URLs in chat/model payloads.

Update the Conversation card to show per-item review/Confirm and confirmed-draft status. Replace stale UI/model instruction text saying draft execution is unavailable with the narrow truth: the chat records intent; manual controls review and confirm a draft after Previewizer. Do not add a model action, tool call or larger 24 KiB payload. Other selected posts can remain pending; this is not an all-or-nothing batch. The existing preview-first dated-posting guard remains until the goal is explicitly cancelled. Originals, legacy modes, real Library, database, production CP11 and manual publishing behavior stay unchanged.
