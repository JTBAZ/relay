# CP-08c controller and authentication evidence

`src/conversational-planning/routes.ts` exports `registerConversationalPlanningRoutes` with required Prisma, `IdentityService`, lifecycle service, the accepted read-only Autopost lookup, explicit feature settings, a server-trusted `databaseIdentityReady` gate, and a required Studio write guard. Each request passes through the actual `requireAccount` middleware, then reloads the linked Account creator ID and explicitly checks the matching Tenant. The controller constructs the service principal from those server-owned values. File-backed identity configuration fails before session resolution; absent, invalid, and unlinked sessions fail closed. The Studio guard runs only for mutations and cannot construct the principal or authorize a request.

The controller applies exact allowlist matching with trimmed entries, an empty-list deny, and no wildcard. Every route checks Autopost through the injected read-only lookup. `GET /capabilities` reports feature, AI configuration/availability, preparation and entitlement state without constructing a provider. AI availability requires both the opt-in flag and a server-provided valid-config signal; availability is false for creators outside the allowlist. The API uses standard Relay success/error envelopes, trace IDs and `Cache-Control: private, no-store`. Service and infrastructure errors map to bounded HTTP statuses and messages; provider, repository, authentication infrastructure and guard exception text is not returned.

The exported `createConversationalPlanningJsonBodyParser()` enforces a 16-KiB JSON stream limit and Content-Length check for placement before global JSON parsing, and checks byte size when an earlier parser has already populated `req.body`. Route schemas reject extra body/query fields and invalid revisions, IDs, enums, template arrays, handles, patches and cursors before calling the service. Create/revise bind request abort and response-close events to the service `AbortSignal`. Recorded AI replay remains delegated to the lifecycle service so replay can succeed with AI unavailable; new AI availability depends on the composition root omitting provider wiring unless both the opt-in flag and exact model/pricing configuration are valid.

Focused evidence: the combined service/context/intent/route/identity run `npx vitest run tests/conversational-planning/service.test.ts tests/conversational-planning/context.test.ts tests/conversational-planning/intent.test.ts tests/conversational-planning/routes.test.ts tests/identity/require-account.test.ts tests/identity/session-readonly.test.ts` passed all 60 tests. Tests exercise the registered Express routes and actual `requireAccount` with mocked IdentityService and Prisma, including database identity disabled before token resolution, invalid/unlinked sessions, account/Tenant mismatch, exact allowlist and feature behavior, entitlement denial, GET behavior, strict schemas/queries, mutation-only Studio guard, AI-disabled replay delegation, indistinguishable not-found results, already-parsed and Content-Length payload limits, and an oversized chunked request. The focused strict TypeScript check across the route and identity changes passed, followed by the coordinated `npm run build`.

The routes tests mock the service and identity/database boundary; they do not prove real database tenancy or repository behavior. The approved narrow read-only session-resolution option preserves the existing default cleanup behavior, while CP routes pass `{ cleanupExpired: false }` and still reject expired/revoked sessions without deleting them. `tests/identity/session-readonly.test.ts` exercises the actual `DbIdentityStore`, `IdentityService`, and `requireAccount` over mocked Prisma; CP-08e must still prove the expired row remains in PostgreSQL on a real authenticated GET. Existing CSRF/origin middleware placement, actual provider configuration, production session storage and PostgreSQL tenancy remain later integration evidence.
