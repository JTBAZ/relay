# CP-07 PostgreSQL database evidence

This file records the accepted CP-07 database proof for `tests/conversational-planning/persistence-postgres.integration.test.ts`. The guarded test file exercises both raw DDL constraints through `pg` and repository behavior through generated Prisma with `PrismaPg` against a disposable local PostgreSQL database.

Without `CONVERSATIONAL_PLAN_TEST_DATABASE_URL`, the suite is skipped so ordinary repository test runs never contact a database. When the dedicated variable is present, before opening a connection the test requires it to be byte-for-byte equal to the child `DATABASE_URL`, validates a PostgreSQL URL on `localhost`, `127.0.0.1`, or `::1`, allows only a strict set of non-endpoint query options without duplicates/case variants, and requires the exact `relay_cp07_test_<32 lowercase hex>` database name. An unsafe or mismatched configured target fails before connecting. After connecting, it verifies `current_database()` and the exact `relay_cp07_harness:<nonce>` database comment. The fixed proof test must only be run through the disposable harness; it never migrates or drops a database itself. A skipped suite is not database proof.

The authored cases cover enum labels, check/index/FK definitions, nullable unique correlation columns, fail-closed RLS and grants, the tenant provisioning FK, composite creator-scoped child FKs, valid and invalid pointer slot/kind pairs, revision-zero creation, compare-and-swap with two concurrent PostgreSQL transactions, tenant delete restriction, and the absence of authority-row foreign keys/cascades from identity-only pointers. Raw `{}` JSON values satisfy the required fixture columns only; these schema tests do not validate snapshot contents. Test IDs and keys are random per process. All PostgreSQL clients close in `afterAll`/`finally`; the harness retains ownership of database cleanup.

The RLS case creates a random, non-login, non-superuser, non-bypass role only after proving that exact generated role name is absent. It grants that role SELECT on the three composition tables, checks that it sees no rows, then revokes those grants and drops only the role this test successfully created. It does not modify `anon`, `authenticated`, or other pre-existing roles. A local account that cannot create and set this temporary role will not complete the RLS proof; the test fails closed rather than weakening the check.

**Accepted CP-07 proof:** root ran `node scripts/conversational-plan-test-db.mjs --run` after fixing the enum catalog assertion and adding the repository cases. All repository migrations applied to a fresh disposable database, and all 13 PostgreSQL cases passed (6 schema cases and 7 repository/pointer cases). The ordinary database named by the private bootstrap DSN was not migrated. After cleanup, root checked the local maintenance catalog and found zero remaining `relay_cp07_test_*` databases and zero remaining `relay_cp07_rls_*` roles. No database URL or credential is recorded here.

The repository cases use a test-only trusted-context loader with known fixture metadata; persistence, replay, CAS, creator scoping, and pointer ownership queries execute against real PostgreSQL through the generated Prisma client. This proves the repository's database behavior under the supplied trusted context. CP-08 still needs to provide and validate the production server-side source/context adapter. The successful run, complete migration application, ordinary-database isolation, and cleanup checks are the acceptance evidence for CP-07.
