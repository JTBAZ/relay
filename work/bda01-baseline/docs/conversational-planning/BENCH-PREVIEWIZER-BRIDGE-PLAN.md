## Narrow flow

The Conversation panel lists each currently selected post and its preview state. An **Open Previewizer** action requires the active goal and chosen template. For a post with one ready fixture image, the click explicitly chooses that image; if several ready images exist, ask which one before opening. Zero ready images, video or processing media cannot open. The API creates one short-lived attempt for that creator/session/post/source media and returns the trusted Square teaser **initial** config plus a safely XML-escaped synthetic SVG image data URL. This is fixture artwork, visibly labelled as such. The client builds `PreviewizerSession` and opens `PreviewizerOverlay`; it does not send a client-supplied source URL, creator ID or template as authority. The user can adjust the image in Previewizer, inspect its export, and click its existing “Use as preview” control. Closing/cancelling leaves the item pending.

Add a small `bench` hosted mode to the current Previewizer port/client. It uses the current `renderExportCanvas()` → JPEG `onUploadPreview(blob)` → `onComplete({previewMediaId})` path. In this mode, suppress production template list/save, Patreon/Bluesky/destination account reads and real upload calls; hide/disable My Templates, save-template and source-replacement affordances so the selected mock source cannot silently become another file. The root layout already supplies `StudioSessionProvider`; bench mode must still avoid its production effects. Existing standalone/distribution callers keep their behavior. The receipt records the selected template as **initial configuration**, not a claim that the creator left every editor setting unchanged. Do not fork a renderer or fabricate an export receipt from the source image.

The injected mock upload posts the actual JPEG Blob to an authenticated conversation endpoint using a bounded `image/jpeg` raw body, not JSON/base64 or the production staging uploader. The API validates the principal, active goal, attempt ID, selected post/media, source fingerprint, initial template binding, open revision/generation, JPEG type/signature and a 1 MiB byte limit. It hashes the bytes and returns an opaque provisional `previewMediaId`; upload alone is not completion. A separate `onComplete` request supplies that ID and attempt ID. The API checks the same current attempt and promotes its provisional bytes to a completed per-post receipt only after this explicit user action. Exact callback retry returns that receipt without duplicating bytes; a different or stale callback conflicts. No original media ID can satisfy the preview prerequisite.

Keep attempts and completed bytes in the **existing API conversation store**, with one active attempt per session, a 10-minute attempt expiry, 4 MiB retained bytes per session and 32 MiB across active sessions. Enforce caps before accepting bytes and release them on replacement, invalidation, cancellation and idle-session pruning. The receipt includes creator/session/post ID, source media ID and source fingerprint, initial template ID/config hash, exported JPEG hash/size, mock preview media ID and completion revision. A benign chat follow-up can advance the session revision while leaving a completed receipt valid for the same selected post, source and template. Removing that post, changing its source or template, cancelling the goal or expiring the session invalidates the affected receipt; an in-flight attempt becomes stale on **any** turn/revision change. Reopening a changed item requires a fresh export. Snapshot data exposes only item status and small receipt metadata, never Blob bytes, raw source content or a claim of publication.

Keep the existing preview-first dated-posting guard. When every selected item has a valid mock receipt, report that mock previews are ready and X draft creation is **still unavailable** in this ticket. No model schema, second provider call, 24 KiB chat payload change, V1/V2/V3 token change, database table or production CP11 provenance change is needed. The next draft ticket can consume only these server-owned export IDs after its own review and confirmation.
