## Approved implementation and rollout

- Campaign, tier, post, and media-revision identities use versioned JSON-tuple hashes. The shared legacy encoder remains available for reads and targeted seed cleanup. Runtime ingestion creates no new ambiguous legacy keys; existing keys and first-seen times are retained. Deletion keys remain `ingest_deletion:v1:`. Tier-expansion revision strings and the current-state access-transition exception from ticket 04 remain intact.
- Before applying a batch, compatibility checks resolve all potentially applied identities against the loaded snapshot. Unambiguous legacy tuples are sufficient replay evidence. Delimiter-bearing tuples require exact current entity or version-history evidence, or an operator decision. Another matching owner or missing history alone cannot authorize import. An unresolved identity stops the whole batch before snapshot mutations or event publication, including when it appears after otherwise valid new work.
- File snapshots retain current campaign/tier strings and post/media revision history. Database snapshots retain post versions and media version JSON but normalize campaign/tier timestamps. The optional snapshot metadata `legacy_timestamps_normalized` prevents those normalized values from being mistaken for original identity evidence. It requires no database column or migration. File reads now propagate corruption and read failures instead of manufacturing an empty store; only a missing file initializes an empty snapshot.
- The local `scripts/reconcile-ingest-replay.mjs` command accepts a validated batch, a decisions JSON file, and an explicit existing canonical file or configured database. Exact `already_processed` decisions supply replay evidence; exact `import_once` decisions admit unresolved imports through normal ingestion once. Existing all-paid access transitions still follow ticket 04. Invalid actions, duplicate decisions, foreign creators, unused identities, and stale decisions without markers fail before writes. Public HTTP bodies cannot supply overrides. Unresolved synchronous calls keep the generic INTERNAL 500 contract; queued failures retain bounded retries and dead-letter records with the conflict reason.
- Before deploying, drain ingestion and replace old API/worker writers together. Back up the active store. Stop writers before operator reconciliation. Retain legacy markers and original dead-letter records. Old code cannot read v2-only imports; rollback requires retaining a v2-capable reader or a separately reviewed recovery plan. No deployment, live reconciliation, marker reset, bulk import, schema migration, concurrency redesign, or broader retry framework is part of this ticket.
