# PS-12 proposed media repair design

Status: proposed, 2026-10-20. Design preparation only. Implementation waits for PS-11 approval and supervisor GO. Requirements: [PS-12](PHASED-BUILD-PLAN.md) and [R12](ACCEPTANCE.md). Recheck shared signatures against accepted PS-11 before editing. No implementation, migration, test pass, deployment or live-provider acceptance is established here.

## Existing seams and deployment boundary

[ExportService](../../../src/export/export-service.ts) loads all creators in exportMedia, pipeLibraryZip and materializeManifests. Export reuse checks the index revision without checking the file. Downloads overwrite media/{id}/asset; late completion can replace newer bytes. [FileExportIndex](../../../src/export/export-index.ts) has uncoordinated whole-index writes and treats every read failure as empty. [Storage-key mutation](../../../src/ingest/media-storage-key.ts) has no expected revision; the [DB preserved-media lane](../../../src/ingest/canonical-store-db.ts) ignores storage-key-only changes.

[Gallery readiness](../../../src/gallery/query.ts) accepts any index entry or storage key. [Ingest](../../../src/ingest/apply-batch.ts) can inherit a storage key across revisions; content fallback can therefore label old bytes with a new head.

[Dockerfile](../../../Dockerfile) declares no persistent mount; [compose](../../../docker-compose.yml) supplies only Postgres/n8n volumes. [Environment wiring](../../../src/relay-server-env.ts) forwards an optional export root, whose server default is local disk. These files do not establish shared API/worker storage. The [cloud contract](../../architecture/multi-tenant-cloud-runtime.md) targets PostgreSQL/R2; the [relational contract](../../database/relational-model.md) puts durable work in PostgreSQL.

Use bounded DB repair/progress/source-proof state for hosted workers. Keep blob metadata in existing MediaAsset version metadata and reuse [R2 PUT/GET helpers](../../../src/storage/relay-upload-r2.ts). R2 supplies bytes, not file-index locks. Keep the file index for local or explicitly verified shared, persistent, lock-capable roots; matching path strings alone prove neither sharing nor durability. Do not add a blob inventory or storage backend.

## Revision-safe publication

Use loadForCreator for all three scoped ExportService loads. Capture creator, media ID, version sequence, revision, URL, status and current key before I/O. Resolve native/R2 assets through existing paths.

Download outside transactions with existing [bounded retry rules](../../../src/export/fetch-retry.ts), plus explicit byte/time limits. Use immutable revision/content-digest paths. Local writes use a unique temporary file, completed checksum/length validation and atomic rename; R2 publication uses an immutable tenant-scoped key. Never overwrite the currently referenced object.

Add a narrow canonical storage-acceptance method. Under the existing canonical creator lock, reread and conditionally update the same creator/provider/media head, including expected sequence, revision, URL, active status and prior key. Commit currentStorageKey, matching version proof and the claimed repair generation's completion together; retain unrelated fields, parent links and audit identities. Do not save a fetched full snapshot or invoke the destructive refresh lane for storage alone. A stale success or failure cannot replace current metadata, clear newer success or mark newer work complete.

Store checksum, length, key and accepted revision with the existing version metadata; derive the hosted export-index view from it. A narrow index interface must reach ExportService, GalleryService and manifests; canonical types/load/save must round-trip the proof. Publish file-index success only for the accepted head. A crash between blob creation and metadata acceptance leaves an unreferenced immutable object, not false completion. Retry reuses a verified matching object. Retain uncertain orphan objects. Cleanup requires a grace period and proof that no current or retained version references the key; the existing purge worker supplies no such proof. Do not enqueue deletion merely because an attempt became stale or add a broad sweep.

Give FileExportIndex a full read/mutate/atomic-replace lock, strict creator/path/schema validation and ENOENT-only initialization. Merge individual successes/failures under that lock. File mode can avoid canonical rewrites only when manual Retry and every read check current revision and actual bytes; retain legacy/native behavior without relabeling unverified old exports.

## Durable source and download repair

Keep at most one current work/proof row per creator/provider/post or media, plus a bounded discovery cursor. Persist expected-head fingerprint, generation, due time, attempts, lease owner/expiry, safe failure reason and last verified result. The small additive migration needs tenant binding, due-work indexes, RLS/revokes and existing purge semantics; store no cookies, tokens or raw responses. Completed post proof distinguishes unknown collection, verified empty and verified media collection; blob completion is separate. Accept source proof only after the matching post/media state commits; a bookkeeping failure leaves retryable unknown coverage. Legacy imports begin unknown. OAuth returning zero media, missing relationships/included resources or a failed cookie request cannot prove text-only completion. Only a validated complete response can establish empty media.

Seed bounded canonical candidates independently of publication timestamps, discovery watermarks and newest-post probes. Save scan continuation only after work is durable; wrap fairly through creators and older IDs. Ingest can request repair after accepted work, while periodic scanning closes the crash gap. Exclude deleted/native records. Recheck canonical state when claiming, after source refresh and before publication.

Use a separate BullMQ repair tick through the existing [queue names](../../../src/jobs/queue-names.ts), [scheduler](../../../src/jobs/schedule-bullmq-repeat.ts) and [workers](../../../src/jobs/register-workers.ts). Keep [createApp wiring](../../../src/server.ts), [API startup](../../../src/main.ts) and [dedicated worker startup](../../../src/worker.ts) consistent. DB state remains authoritative after lost dispatch, lease expiry or exhausted queue attempts; retry with bounded backoff. Do not mix repair with signed-delete receipts. Bound candidates, provider calls, concurrency, attempts, bytes and run time; never hold DB/file locks during network work.

Reuse [PS-09 targeted collection](../../../src/patreon/patreon-sync-service.ts) and its fences: verify campaign ownership, accept authoritative access before cookie/media waits, then merge current media without republishing the post. Restored cookie consent makes old unknown/incomplete posts eligible. Expired download URLs request one bounded current-source refresh before retrying the current asset head; 403/timeout never proves deletion. Missing/rejected cookies remain actionable waiting states. [Cookie mapping](../../../src/patreon/cookie-scraper.ts) must expose collection completeness instead of silently dropping unresolved relationships.

## Readers, compatibility and verification

Preserve POST /api/v1/export/media and Library Retry in [GalleryGridTile](../../../web/app/components/GalleryGridTile.tsx) and [ActivePostPresenceCard](../../../web/app/components/ActivePostPresenceCard.tsx). GET content/preview/thumb/ZIP/health reads schedule no work. Align imported-media readiness, manifests and content resolution on current-revision proof plus readable bytes; a key alone is insufficient. An upstream read fallback does not establish durable export completion. Keep existing entitlement/mature/owner checks, native upload statuses, R2 objects, SubscribeStar lanes, curation and media-linked audit records.

Extend [retry](../../../tests/export-media-retry.test.ts), [storage key](../../../tests/media-storage-key.test.ts), [content](../../../tests/export-content-source.test.ts), [export](../../../tests/workstream-c.export.test.ts), [ZIP](../../../tests/library-zip-export.test.ts), [health](../../../tests/export-health-route.test.ts) and [access](../../../tests/patron-media-export-access.test.ts) tests. Add actual PostgreSQL head-change/rollback/guard tests, two-process file-index writers/corruption tests, and BullMQ restart/lost-dispatch/lease tests. Cover both [PS-12 baseline gaps](../../../tests/patreon-sync-baseline.test.ts), late cookies, renewed URLs, deleted/shared assets, missing blobs, inherited stale keys, equal-revision URL renewal, stale success/failure, cross-creator IDs and API/worker delivery with separate local disks. Retain [shared-media](../../../tests/canonical-store-shared-media.integration.test.ts) and [targeted audit](../../../tests/patreon-targeted-post.integration.test.ts) regressions.

Hosted readiness requires shared DB/canonical/credentials and Redis, plus R2 or a verified shared export root. Drain old mutable-path/index writers before relying on new publication guarantees; legacy proof stays unknown until checked. Run scoped review, focused/connected checks and root build after implementation. PS-15 retains production migration, real Patreon/browser authentication and bounded rollout acceptance.
