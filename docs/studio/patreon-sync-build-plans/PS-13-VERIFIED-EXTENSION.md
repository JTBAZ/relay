# PS-13 local verification: extension consent and credential checks

2026-10-21. Local implementation and scoped review evidence for [PS-13](PHASED-BUILD-PLAN.md#ps-13-restrict-the-extension-to-verified-consent-and-bounded-collection), [R13/R14](ACCEPTANCE.md), and the [accepted design](PS-13-DESIGN.md). This record does not close PS-15 or authorize deployment.

## Implemented boundary

Every credential check, including an unchanged browser cookie, now sends authenticated `POST /api/v1/patreon/cookie/check`. A successful response acknowledges readable Relay credential storage. It does not verify the Patreon account identity or establish complete data sync. Browser observation, server check/upload acknowledgment, and data-sync evidence remain separate; unknown data-sync time stays unknown.

The [bound extension state](../../../extension/src/lib/storage.ts) includes installation, token, Relay account, workspace, and generation. Legacy grants receive a generation and unknown credential state. Serialized writes and response guards prevent old checks, consent replies, or 401s from overwriting/disconnecting a newer grant. Server authority decides sliding 30-day grant validity rather than cached issuance expiry.

The [vault transition](../../../src/auth/cookie-store.ts) authenticates valid ciphertext before acknowledging it. Automated rotation uses the existing atomic storage transition and preserves original `stored_at`, including at day 89. Missing, deleted, rejected, expired, or unreadable storage cannot be silently restored. Fresh authorization captures the current browser cookie; grant issuance and optional capture have separate outcomes. Existing explicit web/manual save remains available. Cookie/status GET and its direct session resolution perform no expiry cleanup, credential pruning, or grant renewal. Full health GET purity and proactive OAuth maintenance remain [PS-14](PS-14-DESIGN.md).

Fresh capture exposed the old process-local replay limitation. The server now claims the signed code through the existing shared atomic OAuth claim before grant or cookie effects; every failed/nonclaimed result fails closed. Random signed nonces distinguish new consent attempts. The only schema addition is enum member `extension_consent`, in [the Prisma migration](../../../prisma/migrations/20261021010000_extension_consent_claim/migration.sql), SHA256 `44d79c19ffaf632de925e4e3767c7cd3a5d910da2017ff0be9d39f3a23400ad4`. It was applied only to the guarded private database. Deployment requires this enum before new API writers; incompatible old consent writers must be drained. Missing enum support fails closed without a process-local fallback.

[Metrics fetching](../../../extension/src/lib/patreon-post-metrics-fetch.ts) uses browser-managed credentials, one validated linked-post request, and bounded body/time limits. Useful partial observations can be saved, but missing requested counters or a failed page capture return `partial_capture`; positive snapshot count alone cannot mean success. No scraping scheduler, endpoint sweep, or background scraping tab was added. Posting, reminders, origin restrictions, and manual fallback remain in place. PS-12 media repair discovers a successful fresh capture on its next ordinary bounded sync or independent 60-second pass; consent/check handlers do not run inline repair.
