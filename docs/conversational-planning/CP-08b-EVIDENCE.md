# CP-08b lifecycle service evidence

Implemented the internal lifecycle service in `src/conversational-planning/service.ts`. Its factory accepts the accepted `PlanningContextSource`, `ConversationalPlanRepository`, and an optional injected `PlanningProvider`; it does not construct or configure a provider. The principal is a typed server input and every service method checks its bounded account and creator identifiers.

Create and AI revise enforce the 4,000-character request bound, media/post/template selection counts, exact request keys, mutation key and handle-ref shapes. Both perform repository replay lookup before provider availability and fresh model context work. AI revise loads the current plan and enforces its base revision and proposed status before provider use. Compiler clarification, limitation, unchanged and provider outcomes remain separate closed results. Compilers receive the accepted lookup and real calendar resolver; no `confirmedTimes` evidence is supplied.

Manual revise accepts only the persistence patch discriminators, validates exact fields and bounds, applies sparse edits to cloned steps, synchronizes a distribution step's title and `copy_title`, and preserves all other snapshot fields. Manual copy values must be literal creator titles, so clients cannot claim compiler or verified-part provenance. The full candidate is shape- and fresh-context-validated before the repository CAS. Approve and cancel use the existing replayable review commands after a fresh context check. Preview is a deterministic projection of the stored snapshot and checked pointers. GET descriptors use the pure snapshot descriptor function and include all 32 possible steps without model context projection. Confirm returns `preparation_unavailable` without an adapter; with an adapter it reloads the current checked plan and pointers, rejecting a changed approved revision.
