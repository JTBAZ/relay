# BPS-01: schedule a confirmed mock X preview draft

Status: accepted for the temporary mock slice, 2026-10-19; Sol High planned / Luna High implemented / root reviewed. [Evidence and known failures](../../outputs/editor-bench-preview-draft-schedule-proof.json). BPX-01 already creates an **unscheduled** mock X plan and draft variant from a confirmed Previewizer JPEG. This ticket schedules one explicitly chosen confirmed variant at a time. It adds a temporary manual posting cue to the existing bench schedule adapter; it does not create a durable Schedule Rail row or publish.

## Contract

In the existing Conversation, show all confirmed X drafts belonging to the current API-owned session, including drafts whose source card was later deselected. Each row shows its exact confirmed `postText`, the pinned export thumbnail/link, source label, and unscheduled or scheduled state. The user chooses one variant and enters a calendar date (`YYYY-MM-DD`) and local time (`HH:mm`) for **Europe/London**, then selects **Review schedule**. `POST /conversation/x-draft/schedule/review` accepts only `{sessionId,revision,variantId,localDate,localTime}`. Require the authenticated creator and an immutable BPX creation receipt in that session; match its plan/variant IDs, original source version, exact copy, preview ID and JPEG hash to the adapter and pinned bytes. Do not rebuild copy or media from current selection, template, preparation choice, fixture, or original media. A later change to those choices must leave a previously confirmed draft schedulable while its session and pinned export remain alive.

Resolve the supplied date/time with the existing `resolveAbsoluteTime` and trusted server clock in `Europe/London`; reject invalid or already-past UTC instants. Review shows the **resolved** local time and UTC instant, so a daylight-saving gap adjustment or fold choice is visible before confirmation. It shows exact outgoing X copy and the actual confirmed JPEG. Review is read-only and says this is an ephemeral mock manual cue. It cannot substitute an original image, fabricate an export, or silently shorten X copy to the manual-event title limit.

The single pending schedule review has a distinct signed token, at most 8,192 bytes, with ten-minute expiry. Bind creator/session, pending ID, session revision/generation, draft identity and plan/variant IDs, current unscheduled variant state, confirmed source/export/copy hashes, and resolved UTC due time. A new turn, manual toggle, new review, or changed session revision/generation invalidates an unconfirmed review. `POST /conversation/x-draft/schedule/confirm` takes only `{sessionId,reviewToken}`. Under the existing session `confirming` guard and mutation guard, recheck ownership, active pending token, unchanged draft rows, pinned JPEG hash, expiry and future due time immediately before commit. A stale, foreign, missing, altered or already scheduled draft conflicts without writing.

Add a narrow `scheduleDraft` operation to `createBenchDistributionVariantAdapter`'s **existing saved draft entry**. Keep immutable creation facts/rows and BPX creation receipt intact; store a separate current variant row with the same ID, `status:'draft'`, exact copy and preview-only media binding, plus `scheduledFor` set to the reviewed UTC instant. In the same synchronous adapter commit, add one `CreatorScheduleEventWire`-shaped mock row (`manual_event`, `make_post`, X, pending, same due time, `media_ids:[]`) linked to the *existing* plan/variant IDs. Its title is the exact confirmed X copy, which may be 280 characters; do not route through the 200-character manual cue title parser. The event has no real Library `post_id`, no production attachment and no publishing authority; the variant's preview-only binding remains the sole media reference. Use the existing V3 mock event shape/validation where it fits, without creating a second variant or calling the production `CreatorScheduleEvent` database service with `bench_*` IDs.

The adapter checks expected unscheduled state again after any asynchronous test hook, then installs current variant and event together or neither. One confirmed draft gets one schedule in this slice; a different date after confirmation requires a later rescheduling ticket. Keep one immutable schedule receipt per successful review token (bounded to 64 in the session). Retrying that **exact** successful token returns its recorded event/schedule receipt plus the current conversation snapshot, even after later turns; another stale token conflicts. BPX creation-token retries still return the original unscheduled creation receipt, not the later current row. Distinct confirmed drafts, including those from the same original artwork, may each be scheduled. Schedule cues and pinned JPEGs expire with the mock session; adapter rows left after expiry are unreachable through creator/session reads and remain under the existing 1,024-row cap. No new job or blob store.
