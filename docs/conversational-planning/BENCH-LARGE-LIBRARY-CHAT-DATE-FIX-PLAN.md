## Smallest contract change

Keep the one-call, complete-vocabulary architecture and the shared `resolveDatePredicate` and `resolveRealLibrarySelector` matcher. For the mock handler only, construct a **request-specific Structured Outputs response schema** immediately before `provider.respond`. Derive bounded date candidates from literal spans in `latestRequest`, using the existing supported date grammar: `today`, `yesterday`, `this month`, `last month`, ISO `YYYY-MM-DD`, ISO `YYYY-MM`, and month name plus year. Candidate discovery is only a lexical scan of those formats; it does not decide which date field or comparison the user meant. Verify each candidate with the existing `resolveDatePredicate` against the trusted Europe/London clock. Use exact source substrings for `requestQuote`; relative candidate values remain symbolic. Each schema branch couples one `value` and one `requestQuote` as single-value enums, with `field` restricted to `created_date` or `published_date`. Its `op` enum is `on` for today/yesterday, `in_month` for relative or absolute months, or the existing five day operators (`on`, `before`, `after`, `on_or_before`, `on_or_after`) for an absolute day. Thus a day uses one branch, not five. The model still chooses the field, day comparison, logical group, and refinement mode from the request. If no candidate exists, omit the date branch entirely. Reject candidate overflow or request/schema bytes above the existing 16 KiB cap **before** provider dispatch; do not sample dates, truncate the schema, or fall back to an unrestricted date branch. Cap the number of distinct candidate pairs (suggest 16, then apply the 16 KiB bound). Do not mutate the shared public schema object.

The mock schema must otherwise retain the exact existing `{result:anyOf(selection,clarification)}` structure, metadata predicates, add/catalog constraint, and null intent. Keep `REAL_LIBRARY_MODEL_RESPONSE_SCHEMA`, the public grounded route, and the existing <=40 interpreter behavior unchanged. A narrow schema factory in `real-library-selection.ts` that accepts only the selector predicate schema is acceptable if the exported public constant remains structurally identical; the mock may instead build its own schema from the same pieces without duplicating semantic selection logic. Validate provider output against the **same request-specific schema actually sent** before checking the existing vocabulary guard. Keep `resolveDatePredicate` validation in that guard and the full-snapshot matcher. Never rewrite a model date value or quote after generation, infer a different date, or call the model again to repair it. A wrong field/operator or omitted criterion remains a quality failure caught by the oracle.

Add a terse prompt instruction for dates: use exactly one supplied candidate's `op`, `value`, and `requestQuote`, choose the field and comparison from the user request, and clarify when no offered candidate expresses the request. Include candidates in the compact model input, with no post rows, dates, descriptions, selected IDs, or extra catalog calls. The 40- and 1,001-post initial requests must still produce identical serialized `{input,tools,responseSchema}` bytes.
