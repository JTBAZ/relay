# CP-08d server registration evidence

CP-08d wires the opt-in planning routes into the real Relay application. The conversational-planning JSON parser is mounted at `/api/v1/conversational-planning` before the shared `express.json()` parser. Its 16-KiB bound applies to content-length and chunked requests; when no Prisma client is configured, the prefix returns a traced `503 DATABASE_IDENTITY_REQUIRED` after parsing instead of falling through to a 404. Existing global JSON parsing remains in place for other API paths.

When Prisma is present, the composition root creates the production `PlanningContextSource`, Prisma plan repository, lifecycle service, and route controller. The controller receives the actual `IdentityService`, `databaseIdentityReady` from `useDbIdentityStore(config)`, the source's entitlement lookup, and the existing relay mutation and Studio sync guards. It does not receive an alternate authorization callback. Preparation remains unavailable.

The composition root constructs one `FileProviderBudget` at `join(RELAY_GALLERY_EDITOR_DATA_DIR ?? ".relay-data", "gallery-editor-budget.json")` and injects that instance into the gallery editor route and planning provider. Constructing the ledger object performs no file access; reservations remain part of provider calls. Gallery routes retain their existing fallback budget path when no budget is injected.

Planning provider construction requires both exact `1` feature flags, a nonempty allowlist without a wildcard, the exact nonblank `LIBRARY_EDITOR_INTERPRETER_MODEL`, a valid pricing row keyed by that exact model, and a nonblank `OPENAI_API_KEY`. The provider uses the shared budget and fixed `development` phase. If any requirement is absent or invalid, the service has no provider; manual work and recorded replay remain available through the service. Capabilities do not construct a provider.

`server-registration.test.ts` covers provider configuration and mocked budget reserve/settle inputs, exact shared-budget identity passed through both `createApp` registrations, the gallery fallback path, actual `createApp` parser ordering with bounded content-length and chunked requests, the no-database error path, and the already-parsed request path. The wiring test spies only at the factories/route registrations; the separate parser test uses the real `createApp` path. These tests do not exercise a real database, read the on-disk ledger, or make provider network calls. CP-08e remains responsible for production runtime verification.
